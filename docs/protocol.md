# AJBLE119 BLE 协议

私有协议，来自微信小程序「智联微控」（开发者：广州安聚物联网科技有限公司）的 `pages/AJBLE119/AJBLE119.js` 静态分析。帧值的唯一事实来源是 [`web/js/protocol.js`](../web/js/protocol.js)，本文示例均由它直接生成。

## 0 通用规则

| 项 | 规则 |
|---|---|
| 帧边界 | 首字节 `A5`，第二字节为类型（`5A`/`5B`/`5C`/`5D`/`5E`），末字节 `FB` |
| 字节序 | 多字节字段大端；恒温 `0x0001` 在线路上是 `00 01` |
| 校验 | 9 字节控制帧 `CHK = 前 7 字节累加 & 0xFF`；15 字节预约帧**无校验** |
| 分片 | MTU 默认 23，22 字节状态帧常拆成 `10+12` 两次通知，须按字节流拼到 44 hex 再解析 |

## 1 控制帧（9 字节）

`A5 5A cmdH cmdL p1 p2 p3 CHK FB`

| 命令 | 命令字 | 取值 | 示例帧 |
|---|---|---|---|
| 电源 | `0x0000` | p3：0=开 / 1=关 | `A5 5A 00 00 00 00 00 FF FB`（开） |
| 恒温温度 | `0x0001` | p3：0=关，30/40/50/60/70/80（℃） | `A5 5A 00 01 00 00 32 32 FB`（50℃） |
| 全控档位 | `0x0002` | p3：0–5 | `A5 5A 00 02 00 00 03 04 FB`（3 档） |
| 右前加热 | `0x0003` | p3：0–5 | `A5 5A 00 03 00 00 02 04 FB`（2 档） |
| 右后加热 | `0x0004` | p3：0–5 | `A5 5A 00 04 00 00 02 05 FB`（2 档） |
| 左前加热 | `0x0005` | p3：0–5 | `A5 5A 00 05 00 00 02 06 FB`（2 档） |
| 左后加热 | `0x0006` | p3：0–5 | `A5 5A 00 06 00 00 02 07 FB`（2 档） |
| 脚暖 | `0x0007` | p3：0–2 | `A5 5A 00 07 00 00 01 07 FB`（1 档） |
| 提示音 | `0x0009` | p3：0=静音 / 1=滴滴 / 2=语音 | `A5 5A 00 09 00 00 00 08 FB`（静音） |
| 定时 | `0x000A` | p2=时 / p3=分；`00:00` 取消 | `A5 5A 00 0A 00 04 23 30 FB`（04:35） |
| BLE 功率 | `0x000D` | p3：1=低 / 5=中 / 9=高 | `A5 5A 00 0D 00 00 05 11 FB`（中） |
| 音量 | `0x000E` | p1：0–100（**注意在 p1**） | `A5 5A 00 0E 50 00 00 5D FB`（80） |

## 2 查询帧

`A5 5B 00 00 00 00 00 00 FB`

发一帧、下位机回一帧 22 字节状态。原小程序进页面 3.5 s 发一次；本仓库固件按 `query_interval: 10s` 轮询。

## 3 状态帧（22 字节）

`A5 5C` 开头，共 22 字节 / 44 hex；byte21 是前 21 字节累加和，解析时不校验。

| 字节 | 含义 | 取值 |
|---|---|---|
| 0–1 | 帧头 | `A5 5C` |
| 2 | 电源 | 0=关 / 1=开 |
| 3 | 恒温目标 | 0=关，30/40/50/60/70/80 ℃ |
| 4 | 全控档位 | 0–5 |
| 5–8 | 四区档位 | 左前 / 左后 / 右前 / 右后，各 0–5 |
| 9 | 脚暖 | 0–2 |
| 10 | 提示音 | 0=静音 / 1=滴滴 / 2=语音 |
| 11–13 | 定时 | 时 / 分 / 秒 |
| 14–16 | 预约 | 日（0=无 / 1=今天 / 2=明天）/ 时 / 分 |
| 17 | 预约温度 | 40–80 ℃ |
| 18 | 当前温度 | ℃ |
| 19 | BLE 功率 | 1 / 5 / 其它 |
| 20 | 音量 | 0–100 |
| 21 | 累加和 | 前 21 字节累加 `& 0xFF`，解析时忽略 |

示例（开、恒温 50℃、提示音滴滴、当前 23℃、BLE 中、音量 80）：

`A5 5C 01 32 00 00 00 00 00 00 01 00 00 00 00 00 00 00 17 05 50 A1`

## 4 下位机断开帧

`A5 5D 00 08 00 00 00 0A FB`

设备主动要求断开（常见于被手机小程序抢连）。收到后应 `disconnect()` 并提示用户，本轮轮询内不要继续写特征。

## 5 预约帧（15 字节，无校验）

`A5 5E day HH MM temp 00 00 00 dayOff minOff 00 00 00 FB`

| 字段 | 含义 |
|---|---|
| `day` | 0=取消，1=今天，2=明天 |
| `HH` / `MM` | 预约时刻，0–23 / 0–59 |
| `temp` | 预约温度 40–80 ℃ |
| `dayOff` / `minOff` | 当前时刻到预约时刻的偏移，由 App 现算、设备端倒计时；负值写字节时 `& 0xFF` 回绕 |

`h`/`m` = 预约时/分，`nowH`/`nowM` = 当前时/分。逐行照抄 `protocol.js` 的 `buildOrder`：

```js
let dayOff = 0, minOff = 0;                          // day=0/其它 → 0/0
if (day === 1) {                                     // 今天；今天已过时不命中任何分支 → 0/0（源码原样）
  if (h === nowH)                       { dayOff = 0; minOff = m - nowM; }
  else if (h - nowH === 1 && m >= nowM) { dayOff = 1; minOff = m - nowM; }
  else if (h - nowH === 1 && m <  nowM) { dayOff = 0; minOff = 60 - nowM + m; }
  else if (h - nowH >  1 && m >= nowM)  { dayOff = h - nowH; minOff = m - nowM; }
  else if (h - nowH >  1 && m <  nowM)  { dayOff = h - nowH - 1; minOff = 60 - nowM + m; }
} else if (day === 2) {                              // 明天
  if (nowM < m)      { minOff = m - nowM; dayOff = 24 - nowH + h; }
  else if (nowM > m) { dayOff = 23 - nowH + h; minOff = (h === 0 && m === 0) ? 60 - nowM : nowM - m; }
  else               { minOff = 0; dayOff = 24 - nowH + h; }
}
```

偏移依赖设备端当前时间：HA 侧必须先同步时间（SNTP 或 HA 时间源），否则预约时刻会错。

示例（当前 14:23，预约明天 09:30 / 60℃，`dayOff=0x13=19`、`minOff=0x07=7`）：

`A5 5E 02 09 1E 3C 00 00 00 13 07 00 00 00 FB`

取消预约：

`A5 5E 00 00 00 00 00 00 00 00 00 00 00 00 FB`

## 6 定时帧

`A5 5A 00 0A 00 HH MM CHK FB`：`HH` 0–23、`MM` 0–59，`00:00` 表示取消。

| 动作 | 帧 |
|---|---|
| 定时 04:35 | `A5 5A 00 0A 00 04 23 30 FB` |
| 取消定时 | `A5 5A 00 0A 00 00 00 09 FB` |

定时只在开机状态生效（关机时设备静默忽略、不回显）；小程序上限 04:59。

## 7 帧值自检

在仓库根目录运行，用 `protocol.js` 重算并比对本文示例，输出 `OK` 即一致：

```bash
node --input-type=module -e "import('./web/js/protocol.js').then(p=>{const h=b=>p.toHex(b);const ok=h(p.buildFrame(0,0,0,0))==='A5 5A 00 00 00 00 00 FF FB'&&h(p.buildFrame(1,0,0,50))==='A5 5A 00 01 00 00 32 32 FB'&&h(p.buildTimer(4,35))==='A5 5A 00 0A 00 04 23 30 FB'&&h(p.buildVolume(80))==='A5 5A 00 0E 50 00 00 5D FB'&&h(p.buildOrder({day:2,hour:9,minute:30,temperature:60,now:new Date(2026,0,1,14,23)}))==='A5 5E 02 09 1E 3C 00 00 00 13 07 00 00 00 FB';console.log(ok?'OK':'FAIL');process.exit(ok?0:1)})"
```
